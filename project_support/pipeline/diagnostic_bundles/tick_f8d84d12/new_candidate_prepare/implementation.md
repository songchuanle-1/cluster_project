# M223-FCB source prototype

FCB replaces three independent token FFNs with a scene-local complete bipartite graph between true fine and true coarse bank tokens. Original3LN yields z_f,z_m,z_c. Each true fine/coarse pair produces q_fc=GELU(pair_map[z_f,z_c]), a C-vector rather than an attention score. Fine and coarse deltas are the two fixed equal marginals of the sameq. Middle delta is GELU(middle_map[z_m,mean_original_fine_parent(fine_delta)]). Pair membership includes each fine's original ancestor and other supported roots; it never includes a padded/unsupported root or a different scene. Original raw banks/FPS/membership/IDs/CSORT/HCG, three raw skips, point readback and single instance-feature update are preserved.

Support is built only by composing true point-supported fine IDs through both original parent maps. One fine row counts once regardless of point count. Production packs active IDs across batches with separate fine/middle/coarse offsets; Cartesian products are constructed inside each scene before packing. q is generated by one pair_map/GELU call; the same Tensor supplies fine/coarse means, then a third fixed mean sends fine_delta to original middle parents. One middle_map/GELU call finishes the core. No raw pooling is changed; no learned scalar weights, softmax, QKV, gates or extra residual is added. No support yields zero deltas and no map call; unsupported/padded slots always receive zero delta. A singleton root/fine uses the same graph without a special numeric fallback.

Compared with CPA, which reads coarse values through point-query scalar dot/softmax and only replaces coarse point gather, FCB has cluster-level nonlinear vector messages and updates coarse as well as fine/middle. CRE first compresses coarse-root pairs and then decodes only from the fine/middle's original root context; FCB conditions every coarse output directly on each true fine before any marginal mean. BEC/APF/AOC use original membership/ancestry factors, while FCB includes nonancestor fine-coarse pairs. These are bounded whole-DAG distinctions within message passing, not a complete novelty proof, new-information guarantee or diagnosed task deficit. Original bank features/readback can already contain global/descendant information.

Both endpoint outputs shareq: their unweighted global means agree algebraically, so they are coupled rather than independently expressive. No FP32 conservation check follows. Global averaging can wash out local evidence; redundant roots, unequal level roles and underused maps may reduce usefulness. No improvement, task bottleneck or rescue of another candidate is claimed. Fine count is cluster count, not point mass. Original constructor creates all old FFNs/LNs in the original RNG order, creates both new default maps inside CPU fork_rng, then replaces old FFNs with Identity. Actual paired common initialization still requires a real native comparison.
