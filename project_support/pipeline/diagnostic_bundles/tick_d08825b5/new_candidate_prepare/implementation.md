# M218-HPC private source prototype

The original three full-bank LayerNorms and FFNs keep their parameter construction, names, shapes and call count. Only CTF.forward in this independent package changes. It prepares true-support forest metadata once, applies S=(I+L)^-1 to the normalized banks, calls each original FFN once, applies S again, then adds each untouched raw bank as its original outer skip. HCG receives exactly these three refined banks. Raw SharedClusterBank construction, FPS, IDs, child_maps, original CSORT on raw banks, decoder wiring and the single inst_feats writeback are unchanged. Six baseline Python files including dec.py are byte-identical. The independent eighth file implements the resolver; the native YAML is byte-identical at a unique package/config path.

For supported fine leaf i, its original middle parent j and coarse root k, eliminating the fine leaves gives a1_j=2+n_f(j)/2 and r1_j=x1_j+sum_i(x0_i/2). Eliminating middle nodes gives a2_k=1+n_m(k)-sum_j(1/a1_j) and r2_k=x2_k+sum_j(r1_j/a1_j). Then z2=r2/a2; z1_j=(r1_j+z2_parent)/a1_j; z0_i=(x0_i+z1_parent)/2. These are ordinary exact-real Schur equations for I+L, not a finite iteration or selected approximation. Production metadata uses Python floating-point diagonal values and native tensor dtype arithmetic; native FP32 numerical behavior is not tested by this source package.

Membership IDs alone are detached/copied to CPU. No feature is detached, serialized or reconstructed through Python. Features use functional index_add/index_select/index_copy and batched level operations; there is no dense inverse/matrix allocation and no per-node tensor kernel loop. There are two solver calls, each looping only over batch. Unsupported/batch-pad rows are isolated identity rows, so the original LN/FFN behavior on those rows is preserved rather than newly zeroed or connected to a sentinel. Real support is recursively derived from original point IDs, not mere adjacency-slot presence.

Parameter delta is exactly zero by unchanged original constructors, not a measured model inventory. All original FFN matmul shapes stay the same. Per solver there are at most [4(N0+N1)+N2]*C elementary vector arithmetic operations over active rows (metadata/indexing/copies excluded); two solves give 659456 operations for supported counts256/64/8 and C256. This is a source operation estimate, not FLOPs from the mandatory original profiler. CPU metadata transfer/synchronization and allocations may affect actual latency/memory; they must remain included in the same original resource measurement. Actual FLOPs, unsupported operator accounting, latency, memory, native autograd, initial weights/batches and efficacy are NOT_RUN/UNKNOWN.

The software proof extracts the actual production plan/solve and actual CTF.forward bodies by AST into a plain Python numeric/list carrier, then compares with an independent full Fraction Gaussian elimination oracle from original IDs. It is not Torch/Tensor/FP32/GELU/autograd verification. The final proof contains36 forest cases, one mixed two-batch case, eight invalid cases and208 aggregated assertions, not208 independent experiments. Original HCG/CSORT/partitioner/bank classes are AST-identical; six other source files and YAML are byte-identical.

Current AEF56 is only a future version-parent compatibility reference. This package has no actual code commit. Root may preserve a separate exact-nine-file clean isolated child only after independent source review. If primary changes before native execution, a fresh compatible version and that version's actual paired testing are required; no sibling fast-forward is assumed. Existing RSTR/PCE/other holds and scientific failures remain unchanged.
