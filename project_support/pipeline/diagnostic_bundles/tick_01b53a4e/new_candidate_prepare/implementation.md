# M219-APF implementation

Eight independent model files plus the original byte-identical YAML are staged under _apf. Six files including dec.py are byte-identical to original M95. hier_postprocess.py only imports the new helper, constructs the new factor after the entire original3FFN/3LN initialization, deletes all three replaced FFNs by replacing their ModuleList entries with Identity, and uses original3LN -> joint path factor -> original raw+delta skips before the unchanged HCG/CSORT/point output path. There is no new gate, query/point routing, repeated inst writeback or outer residual.

The helper uses composed original point->fine->middle->coarse support. build_ancestry_path_plan keeps external IDs and creates compact private parent positions in linear metadata passes. Duplicate points do not duplicate factors. Global flat batch offsets gather exactly one fine/middle/coarse triplet per supported fine row. One Linear3C->3C plus original GELU produces all three views simultaneously. Fine outputs inverse-scatter directly; two functional index_add/count divisions compute fixed equal vector means for middle and coarse, then functional index_copy restores original IDs. All unsupported/pad deltas remain zero; no feature detach/CPU roundtrip exists. Only integer ID metadata uses detached CPU lists. The coarse mean is direct over fine paths and cannot silently become a mean over middle means.

Original constructor RNG consumption is preserved. New default CPU Linear construction is wrapped in torch.random.fork_rng(devices=[]), without manual_seed, initialization search or altered nn.Linear initialization. Subsequent common RNG position is intended to match baseline; actual common initialization and loader pairing are NOT_RUN. Default random sequence reuse may correlate new factor and later common weights; no independence claim is made.

At C256, source-inferred factor parameters590592 replace original3FFN1576704, delta-986112. At original bank caps256/64/8, dense multiply counts are 9C^2*256 versus 8C^2*(256+64+8), before gathers/reductions/CPU synchronization; this is not whole-model fvcore/resource evidence or a latency claim. Native<10G/resources remain NOT_RUN; new gathers/small kernels/CPU metadata can be slower despite fewer inferred dense operations.

The executable static_check.py extracts actual production plan/prepare/mean/forward bodies and uses a plain Fraction/list Tensor interface with diagnostic linear-map and identity-activation stubs. It checks original-ID incidence, batch offsets, unequal-degree coarse means, singletons, empty/zero-batch handling, exact private reductions/call counts and unchanged inputs. It does not execute Torch, real Linear/GELU, autograd, FP32, native data, optimizer or resource measurement. First checker failed only while serializing AST hashes after reusing the forward symbol; the initial checker/failure JSON are retained. No model source changed to repair that harness issue.

Current source/code/actual parent remain null. Reference parent56 is only current compatibility context; future actual version must be compatible with then-current main and freshly tested. No old CRE/HPC/AEF result, failed import, hold or implementation revision is relabeled or reopened. The current original M95 dependency-import issue is an operational prerequisite for future native work, not APF evidence.
