## The low-level empty-input risk is concrete

In `framework/lib/pointgroup_ops/src/voxelize/voxelize.cpp:59–118`, N=0 produces no output rows, but the rulebook outer vector is resized to two entries. Its second vector remains empty: modes0/1/2 push entries only inside nonempty-output loops; active mode4 does so at140–149.

Consequently line30 evaluates `&voxelizeRuleBook[1][0]` on an empty vector if called with N=0. That is an invalid vector subscript/undefined behavior, even though the called output loop at36 would have zero iterations. This establishes an API-level precondition gap, not a guaranteed segmentation fault on every build or proof of this run's fault.

The Python extension wrapper (`pointgroup_ops.py:23–30`) explicitly asserts contiguity, but does not explicitly reject N=0 or assert CPU placement. The C++ entry checks rank and column count at13–14; it has no N>0 guard before line30.
