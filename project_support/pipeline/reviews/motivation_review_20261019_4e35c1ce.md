# Motivation Review - cluster_project

## 1. Goal
- 约束主源为本轮已核实的 `pipeline/goal.json`，SHA256 为 `0441fecda02231f3af9abac3ca3e6e8f1a7e8ebce19f1f35293fdda01d765c85`。目标0.5100，历史最佳0.5020，差0.0080。
- 项目动机原文：面向 ScanRefer 三维语言定位，回归用户最初的点云特征更新主线，研究不同层级承担不同注意力/信息交互作用的轻量结构机制，目标 mIoU ≥ 0.51。核心路径是分层信息交互真实更新点云/超点 inst_feats，再与 query 特征共同生成 mask；不能把仅修改监督损失、沿用已有层级骨架或无效路由计算称为该主线创新。以多尺度 context-only 和 M95 为既有对照，先诊断层级互补性、局部细节及跨层信息是否真正进入 mask 特征，再依据证据选择一个可推导、可证伪的结构机制。监督与关系绑定仅作辅助诊断/匹配对照，不再取代主线。覆盖机制对照、泛化稳健性和同口径效率验证；已有收益不证明新的分层注意力有效，也不自动重开历史失败或禁止的路线。

## 4. Gap Analysis
- 明确的新源问题：细层数量使用整个batch最小有效超点数。如果原生训练总有足够超点，代码可能性不能称为实际特征瓶颈。
- 该问题是空间支持分辨率，不是已关闭的零填充全局均值、均值矩缺失或祖先映射问题。定向检索旧ID未找到相同假设。
- 四项旧监督候选仍为辅助优先级保留；GPU1授权不解除。server3当前不可达，不推断空闲。

## 5. Design Rationale
- 先执行原始TRAIN支持数普查，才决定是否需要同场景/不同同伴原生干预。不能先实现无证据的修复。
- 小同伴100与大同伴500的源表达式配对对照验证检测确能识别clamp；实际支持均至少256时不启动单算子修补模型。
- 不创建新模型、不重复索要授权、不改gate、数据、seed或schedule；新颖性和训练效果均未知。
