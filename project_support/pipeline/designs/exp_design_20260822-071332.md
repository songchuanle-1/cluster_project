  - 故事线当前状态:

      context message), M125-MLAY-DCA / M126-MLAY-DCM (2层 legacy × decoder 访问)
    缺口: **decoder 访问轴已排队但全用 context message — detail message (独立有效

  - 这批变体在故事线中的角色: 组合验证 — "消息构造质量 (detail) × decoder 访问路径
    (DCA/DCM)" 交互, 完成 2×2 矩阵, 判定 writeback 瓶颈的归属

## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline）
    - 多尺度 context 深度 (2层 legacy): M86=0.5010, γ=+0.0116 — encoder 侧最强
    - CTF+HCG 1层: M81=0.5012, γ=+0.0118 — 核心架构
    - detail message: D1=0.5003, γ=+0.0109 — 消息构造轴独立有效
  ### 3.2 哪些方向失败（< baseline 或持平）
    - encoder-side token 质量全灭: CCL=0.4890, CGA=0.4926, BCF=0.4926,
      (加 CSORT/ORT/MEMBANK/SRL 已关闭)
    - 结论: ~0.501 平台横跨所有 encoder-side 机制; 瓶颈在 writeback→decoder 通路
  ### 3.3 哪些尚未消融
    - **decoder 直接访问 cluster tokens**: M123-DCA / M124-DCM 排队 (context message)
    - **2层 context × decoder 访问**: M125/M126 排队
    - **detail message × decoder 访问**: 从未组合 — 本次设计的 2×2 第 3/4 格
  ### 3.4 结论
    - 若 writeback 是瓶颈: DCA/DCM 破 0.501; 若 detail 收益在消息构造本身 (token 内容),
      detail×DCA/DCM 应进一步叠加
    - 若两轴冗余: DET×DCA ≈ DCA, 说明 detail 收益已被 decoder 直连吸收 (writeback 有损
      才是 detail 的受益通道) — 同样推进故事线 (判定 writeback 瓶颈归属)
    - 2×2 满格 {context,detail}×{DCA,DCM} 系统判定交互, 避免单轴结论的混淆
