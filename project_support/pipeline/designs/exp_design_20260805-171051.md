## 1. Motivation（为什么设计这批实验）
  - 项目动机（goal.json description）: cluster: 多尺度 cluster context 机制 — cluster bank
    聚合点云特征→cluster_attn 把多尺度 context 回写更新 inst_feats→提升定位精度。注: 原'
    聚类路由'假设已被证伪(routing 生效反降点), 收益来自 context 而非 routing。目标 mIoU ≥ 0.51。
  - 故事线当前状态: context 回写确认有效 (+0.0118); routing 证伪; readback expressiveness /
    融合权重形式 / 聚合方式三轴闭合; detail message 独立有效 (D1=0.5003, γ=+0.0109);
    正确多尺度交付是最大未验证结构空白 (champion 粗尺度 gather 长度错配, 实为准单尺度,
    M65-HCG 已入队 P0 检验)。
  - 触发原因: 队列深度不足: waiting=5 (M58 srv6 + M62/63/64/65 srv4) < 可用槽 5+1=6 → 需补 1。
  - 这批变体在故事线中的角色: **补 {交付正确性} × {message 类型} 2×2 的最后一格** —
    (DRP+context)=champion 0.5012 ✓, (DRP+detail)=M58-DET-DRP 已入队,
    (HCG+context)=M65-HCG 已入队, (HCG+detail)=**M66-DET-HCG 本次**。

## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline 0.4894）
    - 多尺度 context 回写: DRP 0.5012, γ=+0.0118 — 核心机制 (但准单尺度, 见 §3.4)
    - detail message: D1 0.5003, γ=+0.0109 — 独立有效, 与 champion 差 0.0009
  ### 3.2 哪些方向失败（< champion 或持平）
    - readback expressiveness: BIL/NLR/FILM/FLM/DGC 全 < champion (轴闭合)
    - 融合权重形式: SWI 0.4970 / CSF 0.4958 / SCF 0.4927 全 < champion (轴闭合, broken 交付下)
    - 聚合双分支: DCA 0.4893 < mean (mean 最优)
    - 组合: M24-ORT-D(0.4955)/M26-ORT-HYB(0.4998)/E4(0.4944) 无叠加
  ### 3.3 尚未消融 / 结构空白
    - **正确多尺度交付**: 全 56+ 变体 (含 champion) 粗尺度 gather 写前 K_{lvl-1} 点槽,
      多数点中/粗尺度 context=0 → M65-HCG 已入队 (P0)
    - **{正确交付}×{message} 交互**: (correct, detail) 格从未测 — 本次 M66 补格
  ### 3.4 结论
    - 30+ 变体全 ≤ 0.5012, 且失败集中在 message 内容/融合/投影 — 均在 "残缺粗尺度交付" 下测试。
      正确多尺度交付 (HCG) 是故事核心声称的首次真检验; 在其结果到达前, 把最强 message 机制
      (detail, 0.5003) 与 HCG 组合是最低成本的补格, 使 2×2 完整, 无论 HCG 结果如何都可解释。

## 7. Risk Assessment（风险评估）
  - 代码风险: 极低。M66 无新代码 — det_hcg 包 = hcg 包的物理拷贝 (含 C2F_ClusterAttn_HCG 类),
    detail message 分支已在所有 Encoder_layer 中实现 (cluster_message_type='detail')。
    仅 config 加一个参数, 与 M58-DET-DRP (det_drp 包 = drp 拷贝 + detail) 完全同构。
  - 资源风险: 无。无新参数/FLOPs 增量; detail 分支为 F.layer_norm (O(NC)), 显存无增量。
    远低于 FLOPs≤10G。与 champion 相同资源占用。
  - 数据风险: 无。复用 ScanRefer, seed 1999 一致。
  - 失败回退: 若 crash 3 次 → 放弃 DET-HCG, 标记 question, 队列深度回落 5 (需再补设计)。
    但 det_hcg 与已跑通/已入队的 hcg、det_drp 仅差一个 config 参数, crash 概率极低。
  - 语义风险: 正确多尺度 + 残差 message 可能不比 champion 好 (detail 残差可能被正确 context
    吸收) — 此时 2×2 给出 "detail 与正确交付正交/被吸收" 的排除性结论, 仍是故事推进。
