## 1. Motivation（为什么设计这批实验）
  - 项目动机（直接引用 goal.json description）: "cluster: 多尺度 cluster context 机制 —
    cluster bank 聚合点云特征→cluster_attn 把多尺度 context 回写更新 inst_feats→提升
    定位精度。注: 原'聚类路由'假设已被证伪(routing 生效反降点), 收益来自 context 而非
    routing。目标 mIoU ≥ 0.51"
  - 故事线当前状态:
    已验证: context 回写有效 (+0.0118); decoder-access 轴 DCM=0.5010 最优
            (qla 语言通路共享 KV); 2层注入 MLay=0.5010; MFP=0.5020 tie champion
            (机制性未定, M129/M130 判定中)
    已证伪: routing / CSORT 跨 seed / encoder-side token 质量轴 (CCL/CGA/BCF/SRL) /
            detail×DCA 组合 / decoder 专用分支 DCA (0.4970 < DCM 0.5010)
    已排队: M125/M126 (MLay×DCA/DCM), M131 (MFP×DCM), M132 (MFP×MLay), M122 (MLay seed)
    缺口: DCM 验证了 qla 语言通路共享 KV 有效, 但 decoder 的视觉/实例通路 (qia)
          从未注入 cluster context — motivation_review 反复标注 "qia 视觉通路未测"
  - 触发原因: waiting=5 ≤ 可用卡数5 (集群容量 server-4 2槽 + server-6 3槽 = 5),
    深度不足 (要求 waiting ≥ 容量+1=6) → 自主补设计
  - 这批变体在故事线中的角色: 验证假设 "decoder-access 收益通路不变" — DCM 在
    语言通路 (qla) 有效, DCMV 在视觉通路 (qia) 的对称测试, 补全
    {qla, qia} × {cluster KV 扩展} 2×2 矩阵缺格。

## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline）
    - context 回写 (A1): 0.5012, γ=+0.0118 (核心, 已确认)
    - decoder-access 轴 DCM: 0.5010, γ=+0.0116 (方向①最优, qla 共享通路)
    - 多层注入 MLay: 0.5010, γ=+0.0116 (方向②, 2层)
    - MFP aux loss: 0.5020, γ=+0.0126 (机制性待 seed 判定)
  ### 3.2 哪些方向失败（< baseline 或持平）
    - encoder-side token 质量轴: CCL=0.4890, CGA=0.4926, BCF=0.4926, SRL=0.4912 (掉点)
    - CSORT 跨 scale: 3/4 seed 负, 轴关闭
    - DCA (decoder 独立分支): 0.4970 < DCM 0.5010, decoder-access 内对比淘汰
    - detail×DCA: 0.4870 (负交互), detail×DCM: 0.4990 (无叠加)
  ### 3.3 哪些尚未消融
    - **qia 视觉通路注入 cluster context: 从未测试** (本次设计)
    - MFP 机制性: seed 矩阵判定中 (M129/M130)
    - MFP × DCM / MFP × MLay 叠加: 排队中 (M131/M132, conditional on MFP seed)
  ### 3.4 结论
    - DCM 的关键贡献是证明"decoder 侧共享 KV 直读 cluster context 绕过 writeback
      有损瓶颈"有效。但该机制只在语言通路 (qla) 验证过。
    - qia 是 decoder 的第一跳注意力 (query 直接 attend inst_feats), 是实例特征
      的主通路。若 cluster context 能在此通路直接可用, decoder query 在更早期
      就能获得场景级上下文, 与 writeback 后的 inst_feats 并行。
    - 这是当前唯一标注的 decoder 侧未测格, 且机制上对称于已验证的 DCM,
      是最可辩护的下一步。

## 7. Risk Assessment（风险评估）
  - 代码风险: 低。单分支代码变更 (dec.py Decoder_layer.forward), 逻辑与 DCM
    完全对称 (qla KV concat → qia KV concat)。DCM 已在 M124 跑通, 复用其
    cluster_feats_list 构建逻辑 (forward_iter_pred:505-507)。
    注意点: qia 的 mask 是 batch_mask (实例级), 需与 cluster_pad 正确 concat;
    qia 输出 (query_qia) 后续被 qla 消费, 信息流与 DCM 分支独立。
  - 资源风险: 低。与 DCM 相同显存/FLOPs 量级 (无新参数, 仅 KV concat),
    满足 FLOPs ≤ 10G 约束。
  - 数据风险: 无。同一 ScanRefer 数据。
  - 失败回退: 机制独立, 不依赖 MFP seed; 若 crash 3 次 → 放弃标记 question,
    聚焦已排队叠加实验 (M125/M126/M131/M132)。
