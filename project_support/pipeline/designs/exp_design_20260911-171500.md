## 1. Motivation
The authoritative goal asks for one concrete ScanRefer error, one lightweight
mechanism with core novelty and a stepwise derivation, verified primary-source
differences, matched controls, robustness, and efficiency. The current champion
M95 remains at 0.5020 versus target 0.5100 and the queue has no free execution
slot. Scientific admission precedes queue refill.

The immediate question is narrow: the baseline source registers a class-shared
`indi_embedding` for every decoder layer, while M95 constructs a fresh
`nn.Sequential` inside each layer. Before requesting any real head-input capture,
the project must verify whether those source statements produce actual shared
modules, shared parameters, shared storage, duplicate checkpoint keys, and a
cross-layer derivative path.

No new mechanism is admitted by this design. This is an N1/T0 implementation
audit and a negative-control harness.

## 3. Analysis And Direction
### 3.1 Confirmed facts
- The source text differs: baseline calls `add_module` with a class-level
  sequential; M95 creates a new sequential in `__init__`.
- Assignment, ordering, margin, padding, and identity audits are complete and
  reproducible on the frozen diagnostic bank.
- 84 of 90 baseline and 99 of 111 M95 recoverable failures have a usable
  positive and a selected negative under the archived assignment.

### 3.2 Unresolved implementation question
Source text alone cannot tell us whether PyTorch's state dict, optimizer, and
autograd treat the baseline heads as one tied parameter set across all six
decoder layers, or whether M95's per-layer heads are physically disjoint.

### 3.3 Derivation
For layer l, write:

    z_l = h_{theta_l}(x_l) in R^{Q x 2},
    d_l(q) = z_l(q,1) - z_l(q,0),
    m_l(q,h) = d_l(q) - d_l(h).

Let the training objective be a sum of layer-local score terms:

    L = sum_l alpha_l L_l(z_l).

With tied parameters theta_l = theta:

    theta_dot = -sum_k alpha_k J_k^T g_k,
    J_k = dz_k/dtheta, g_k = dL_k/dz_k,
    dm_l/dt = -alpha_l J_l J_l^T g_l
              -sum_{k != l} alpha_k J_l J_k^T g_k.

With independent parameters theta_l:

    dm_l/dt = -alpha_l J_l J_l^T g_l.

The second term in the tied case is a standard coupling term. Its presence is not
novel. The audit will measure whether it exists, its magnitude on a deterministic
synthetic input, and whether finite differences agree.

For the simple independent two-logit case, the previously audited relation still
holds:

    d_q = z_{q,1} - z_{q,0}, p_q = sigmoid(d_q),
    g_q = w_q (p_q - y_q) / M,
    dot(d_q) = -2 g_q.

That relation is a coordinate-level special case and not evidence for a real
training effect.

### 3.4 Novelty boundary
Parameter tying, shared heads, multi-layer auxiliary losses, chain rule, and
Jacobian-vector products are established methods. This tick can only establish
an implementation contract and reject an unsupported causal story. It cannot
claim a new core mechanism.

## 7. Risk Assessment
- Code risk: low; isolated CPU script and no production imports used for
  training.
- Resource risk: none; no GPU allocation and one CPU thread.
- Data risk: none; no ScanRefer samples, annotations, or reserved scenes.
- Numerical risk: ReLU crossing can make the synthetic derivative nonsmooth.
  The worker records the minimum absolute preactivation and the finite-difference
  error; a failed check is reported rather than hidden.
- Causal risk: synthetic coupling is not evidence for a real error, optimizer
  trajectory, or novelty. This is explicitly reported as a limitation.
- Failure rollback: keep the original failed log, apply at most three documented
  helper repairs, and abandon only this diagnostic if it cannot be made exact.
