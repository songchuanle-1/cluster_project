    机制 — cluster bank 聚合点云特征→cluster_attn 把多尺度 context 回写更新
    inst_feats→提升定位精度。注: 原'聚类路由'假设已被证伪(routing 生效反降点),
    收益来自 context 而非 routing。目标 mIoU ≥ 0.51"

    已验证: context 回写有效 (+0.0118); DCM qla=0.5010 (decoder-access 轴最优);
            MLay 2层 legacy=0.5010 (多层注入有效); MFP/CSORT/CTF-token-FFN 全灭。

    **瓶颈定位**: 通路数量不是瓶颈; cluster token 自身信息量 (mean-pool 聚合
            丢失实例判别性) 才是。0.50-0.502 平台已饱和。

## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline）
    - context 回写 (A1): 0.5012, γ=+0.0118 (核心, 已确认)
    - decoder-access 轴 DCM (qla): 0.5010, γ=+0.0116 (方向①最优, 组合轴已关闭)
    - 多层注入 MLay (2层 legacy): 0.5010, γ=+0.0116 (方向②)
  ### 3.2 哪些方向失败（< baseline 或持平）
    - {② legacy}×{DCA,DCM,DCMV} 叠加轴: M125=0.4970 / M126=0.4980 — **全部不叠加**
    - ctf_hcg 2层 (M96): 0.4940 — 退化 base
    - MFP/CSORT/CTF token-FFN: 全灭 (token 非线性变换无监督信号, 无增益)
  ### 3.3 哪些尚未消融
    - **cluster token 实例判别性监督 (CLICA)**: 未测 (本设计)
    - {② legacy}×{DUAL} 正确格: M139 queued
    - {qla,qia}×{cluster KV} 第4格: M134 running
    - seed 矩阵: M135 (running) / M137 / M122 queued
  ### 3.4 结论
    - 平台 ~0.501-0.502 的瓶颈在 **cluster token 自身信息量**, 而非通路数量。
    - CTF (token 加 FFN) 失败说明无监督的 token 变换无意义 → 需要**目标信号**。
    - CLICA (实例对比) 是第一条直接给 cluster token 判别目标的机制,
      与所有已探轴正交, 且不依赖 M134/M139 结果 → 值得独立验证。

## 7. Risk Assessment（风险评估）
  - 代码风险: 中。纯 loss 级变更 + 2 处 forward 输出暴露, 不碰 cluster 注意力
    主干路径; 训练时开启 (train), 推理不受影响。若 crash → 3 次自修复预算。
  - 资源风险: 低。对比损失 328 token 级计算, 显存/FLOPs 增加可忽略; 满足 ≤10G。
  - 数据风险: 无。复用 ScanRefer GT 实例标签 (sp_ins_labels 已在 loss forward 传入)。
  - 失败回退: 独立实验, 不依赖 M134/M139。若 crash 3 次 → 放弃标记 question,
    继续监控队列中组合实验与 seed 矩阵。
  - 备注: 若 CLICA 有效 (γ≥+0.003), 下一步可消融 weight 并尝试与 DCM/MLay 组合;
    若无效, 确认瓶颈非 cluster token 判别性, 平台需范式级新方向 (与 M139 结论交叉)。
