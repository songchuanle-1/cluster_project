## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效 (> baseline 0.4894)
    - Context injection: γ=+0.0118, champion=0.5012 — 核心机制有效
    - Token quality (CTF): +0.0101, 0.4995 — 有效但未突破天花板
    - Detail loss: +0.0109, 0.5003 — 辅助 loss 有效

  ### 3.2 哪些方向失败 (< 0.4950 或未突破)
    - Gate/modulation 系: cag=0.4962, cfe=0.4901, layerscale=0.4921, flm=0.4865 — 四连败
    - Intra-scale cluster attn (C2C): 0.4865 — harmful
    - Injection fusion (SWI): 0.4970 — limited
    - Cross-scale attn (XCA): 0.4954 — failed (but different mechanism from CSF)

  ### 3.3 哪些尚未消融
    - **Readback selection mechanism**: **未验证** — 最高优先级缺口。当前 gather 是硬分配，软分配 (attention-based cluster selection) 从未被测试
    - Cross-scale token interaction (CSF): testing (waiting)
    - Token quality through normalization (CLN): testing (waiting)
    - Token quality through aggregation (WCA): testing (running)

  ### 3.4 结论
    - 0.5012 天花板持续未破，所有已测试方向 (token quality / fusion / gate / intra-scale attn) 均未突破
    - 共同特征: 所有变体保持 hard cluster gather — 每个点只能获取其几何分配簇的 token
    - **NCR 是第一个改变 readback 选簇机制的变体**: 用 top-K attention (软选择) 替代 gather (硬分配)
    - 即使 NCR 失败 (γ≤0), 排除 readback 瓶颈也是重要进展 → 将焦点转向 iterative refinement 或 cross-scale 交互

## 7. Risk Assessment
  - 代码风险: 低 — NCR 是 C2F_ClusterAttn_Lite 的子类, 仅覆盖 _cluster_to_points 方法。继承所有现有 C2F 路由逻辑，仅改 readback 选簇方式
  - 资源风险: 中 — top-K attention over K_lvl=256 tokens per point adds O(N×K×d) compute。预估 +1-2G FLOPs per forward pass, still within 10G limit。需实测确认
  - 数据风险: 无
  - 失败回退: 如果 NCR crash 3次 → 放弃, 关闭 readback selection 方向, 转向 iterative refinement 或 cross-scale readback
