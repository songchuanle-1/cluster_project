## 1. Motivation（为什么设计这批实验）
  - 项目动机（直接引用 goal.json description）: "cluster: 多尺度 cluster context
    机制 — cluster bank 聚合点云特征→cluster_attn 把多尺度 context 回写更新
    inst_feats→提升定位精度。注: 原'聚类路由'假设已被证伪(routing 生效反降点),
    收益来自 context 而非 routing。目标 mIoU ≥ 0.51"
  - 故事线当前状态:
    已验证: context 回写有效 (+0.0118); M86 隔离出多尺度 context 深度是核心收益;
    组合线 (architecture×loss / loss×decoder-access) 多例不叠加 (M146=0.4970 /
    M147=0.4970 / M148=0.4990); M145-ALL 证伪"loss 范围扩展"; **本tick M149-SG
    =0.4940 证伪"对称追逐环是 CSORT 脆弱来源"** (非对称去掉反而丢 0.008, 对称项
    是收益负载)。
    未验证: **去相关轴的操作数 (loss 约束对象)** — 现有 CSORT 家族全部约束在
    源侧 cluster token / 消息构造 (M95 token / M150-M151 写回 / M152-M156 范围与
    对象 / M154 全局 token), 从没人把 abs-cosine 去相关作用到 **decoder 实际消费
    的逐点 scale message** (gather 后的 receiver 侧)。
  - 触发原因: M151 推送后 waiting=4 < 容量4+1=5; server-6 队内无 waiting
    (M122/M156 在跑, 终态后防空转) → 补 2 个 (server-4 + server-6)
  - 这批变体在故事线中的角色:
    M157-PMD: **验证假设X (receiver 侧操作数)** — 去相关轴最后一个未检操作数;
    M158-PMD-SH: **控制组 (内容 vs 结构)** — 保证 PMD 结论可解释, 与 A4-shuffle 同构。

## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline）
    - context 回写 (A1): 0.5012, γ=+0.0118 (核心, 已确认)
    - cross-scale orth (CSORT): 0.5020 (破平台, 对称项 load-bearing, seed 脆弱)
  ### 3.2 哪些方向失败（< baseline 或持平）
    - 交互/注意力/loss 监督: 全灭或关闭 (C2C/CCP/CSF/FLM/pool + M140-144 五连败)
    - **M149-SG (本tick)**: 0.4940 — 非对称去相关掉 0.008 → 对称追逐项是收益负载
    - M146/M147/M148 组合: 0.4970-0.4990 — 组合不叠加再证
    - M145-ALL: 0.4920 — loss 范围扩展有害
  ### 3.3 哪些尚未消融
    - **CSORT 操作数: receiver 侧逐点消息 (本设计 M157)** — 唯一未检操作数
    - **PMD 内容 vs 结构 (本设计 M158 控制组)**
    - write-back 正交 (M150/M151 在队) / 全局尺度 (M154) / 对象对齐 (M155)
      / 尺度范围 (M152/M156) / loss×loss (M153)
  ### 3.4 结论
    - 去相关轴是唯一持续有效方向, 但其变体全在"源侧 token / loss 范围 / 组合"
      上做文章。0.5020 平台 + M149-SG 证伪 → 去相关收益已证明**依赖对称双向往推**,
      但**作用对象** (约束哪个量) 从未系统检查: 源侧原始质心 (M95) → 精炼 token
      (M155) → **逐点交付消息 (M157, receiver 侧)** 是操作数维度的逻辑终点。
    - 每个点 gather 少数 token, 源侧 token 去相关不保证点级收到的消息跨尺度互补 —
      去相关收益可能在 gather 后被稀释。这是"为什么换操作数可能破平台"的因果机制。
    - M158 控制组隔离内容/结构, 防止 PMD 结果被误读 (M145-ALL 教训: 看似扩展
      loss 范围其实是有害的结构压力)。
    - server-6 资源窗口: M122/M156 在跑且无 waiting → M158 挂 server-6 队尾防空转。

## 8. Smell Check (Phase 1.6)
  - M157-PMD: 气味检查 —
    1) 参数增量 0 (loss-only) 且**新计算图**: abs-cosine 惩罚第一次作用在
       composed gather 后的逐点 scale message 上, 梯度路径经 gather + CTF FFN
       (receiver 侧), 与 CSORT (源侧 token) 是不同操作数的信息流。非"在 X 处加
       一个 LayerNorm/Linear/scaling"。
    2) 验证的是**因果假设** "gather 稀释源侧去相关 → receiver 侧冗余独立存在",
       失败结论是机制层面 (源侧已足够), 不是"这个值不合适"。
    3) **超参有依据**: csort_weight=0.01 沿用 CSORT 家族验证值 (同族同尺度),
       无新超参。
    4) 不是数值分布变更 (新增 loss 项改变训练 landscape, 非改某处数值)。
    → 无气味信号 + 通过三标准 → 保留。与 M155-RF (换 CSORT 操作数到精炼 token)
    同族, 但 M155 是源侧 (token), M157 是 receiver 侧 (逐点消息) — 操作数维度
    互补不重叠。
  - M158-PMD-SH: 气味 — 控制组实验 (同 M157 换固定偏移), 零新增参数/超参,
    验证"PMD 收益内容驱动 vs 结构压力"的因果问题。与 A4-shuffle 控制组同构
