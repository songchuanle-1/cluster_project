## 1. Motivation（为什么设计这批实验）
  - 项目动机（直接引用 goal.json description）: "cluster: 多尺度 cluster context 机制 —
    cluster bank 聚合点云特征→cluster_attn 把多尺度 context 回写更新 inst_feats→提升
    定位精度。注: 原'聚类路由'假设已被证伪(routing 生效反降点), 收益来自 context 而非
    routing。目标 mIoU ≥ 0.51"
  - 故事线当前状态:
    已验证: context 回写有效 (+0.0118); decoder-access 轴 DCM=0.5010 最优; 2层注入
            MLay=0.5010; MFP=0.5020 tie champion (机制性未定, seed 对照排队中)
    已证伪: routing / CSORT 跨 seed / encoder-side token 质量轴 (CCL/CGA/BCF/SRL)
    已排队: M125-M128 (decoder 访问 × MLay/detail 2×2 满格), M129/M130 (MFP seed),
            M122 (MLay seed)
    缺口: 多个独立机制均收敛于 ~0.501-0.502 平台, 且 M95=0.5020 已归因 seed 红利
          → 单一机制无法破顶, 缺"正交机制组合"验证。
  - 触发原因: waiting=5 (M125/M126/M129/M130 + M122) < 可用卡数5+1=6
  - 这批变体在故事线中的角色: 验证组合假设 — MFP (encoder 特征完整性) × DCM
    (decoder 共享通路访问) 两条正交有效轴叠加能否破 ~0.501 平台

## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline）
    - context 回写 (A1): 0.5012, γ=+0.0118 (核心, 已确认)
    - decoder-access 轴 DCM: 0.5010, γ=+0.0116 (方向①最优)
    - 多层注入 MLay: 0.5010, γ=+0.0116 (方向②)
    - MFP aux loss: 0.5020, γ=+0.0126 (机制性待 seed 判定)
  ### 3.2 哪些方向失败（< baseline 或持平）
    - encoder-side token 质量轴: CCL=0.4890, CGA=0.4926, BCF=0.4926 (掉点)
    - CSORT 跨 scale: 3/4 seed 负, 轴关闭
    - DCA (decoder 独立分支): 0.4970 < DCM 0.5010, decoder-access 内对比淘汰
  ### 3.3 哪些尚未消融
    - MFP × DCM 组合: 从未验证 — 本次设计
    - MFP × MLay / MFP × DET: 待 MFP seed 判定后决定
  ### 3.4 结论
    - 平台 ~0.501-0.502 由 seed-1999 决定 (M95 已证伪), 单轴机制已到天花板。
    - 唯一未尝试的破顶路径 = 两条正交有效轴组合。MFP (encoder 特征完整性) 与
      DCM (decoder 共享通路) 完全正交 (一个改进 cluster 上游特征, 一个改进
      decoder 下游访问), 且分别是各自轴的最优实现 → 组合是当前最高价值实验。

## 7. Risk Assessment（风险评估）
  - 代码风险: 中。合并两个已验证包的逻辑 (MFP 的 cluster_att + DCM 的 use_cluster_mem),
    无全新算法。风险点: Decoder_layer 签名变更需与调用处一致; cluster_feats_list
    尺寸与 qla KV concat 的 padding mask 处理需正确 (继承 DCM 已验证实现)。
  - 资源风险: 低。DCM 已跑通 (0.5010), MFP 已跑通 (0.5020), 组合显存/FLOPs
    为二者之和量级, 仍 <10G FLOPs 约束; server-4 RTX5090 显存充足。
  - 数据风险: 无。同一 ScanRefer 数据。
  - 失败回退: 依赖 M129/M130 (MFP seed 判定) — 若 MFP 被判 seed 红利,
    M131 撤回 (移出 queue.json) 不跑, 避免浪费槽位; 若 crash 3 次 → 放弃
    标记 question, 聚焦 M125-M128 的 decoder-access 叠加结果。
