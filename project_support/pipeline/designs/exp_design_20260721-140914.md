## 1. Motivation（为什么设计这批实验）
  - 项目动机(goal.json): cluster: 多尺度 cluster context 机制 — cluster bank 聚合点云特征→cluster_attn 把多尺度 context 回写更新 inst_feats→提升定位精度
  - 故事线当前状态:
    已验证: context回写有效(A1−A0=+0.0118), routing有害(A3=0.4468), detail≈context(D1=0.5003)
    正在验证: query融合(M6-QSF), token精炼(M16-CSR), 正交正则(M17-ORT waiting)
    缺口: **多尺度必要性从未被验证** — 是否所有3个尺度(256/64/8)都必要?
  - 触发原因: waiting=1 < 可用卡数2+1=3, 需补 ≥2 个 waiting 任务
  - 这批变体在故事线中的角色: **Scale ablation** — 验证 "multi-scale" 中每个尺度的独立贡献, 为论文 ablation 提供核心证据

## 3. Analysis & Direction
  ### 3.1 哪些方向有效（> baseline）
    - context-only(champion): 0.5012, γ=+0.0118 — 多尺度bank+attention回写
    - detail(D1): 0.5003, γ=+0.0109 — 逐点消息聚合≈均值, 均值足够
  ### 3.2 哪些方向失败（< champion）
    - routing(A3/A4): 0.4468/0.4941 — 内容路由有害(banned)
    - residual(B5/E4): 0.4944 — 上限固定(banned)
    - QGC(M1): 0.4939 — query gate 无增益
    - gate系: 全部 < 0.4962 (banned)
  ### 3.3 哪些尚未消融
    - **尺度必要性**: 从未测试, 优先级 HIGH ← 本批设计
    - **尺度 token 数量**: finer/wider 变体已有 config 但未跑, 优先级 MEDIUM
  ### 3.4 结论
    - Scale ablation 是论文 ablation study 的核心缺失证据
    - 纯 config 变更, 零 crash 风险, 不影响正在跑的 M6/M16/M17
    - 无论结果如何 (尺度必要/不必要), 都对故事线有推进
