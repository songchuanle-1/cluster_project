## 3. Analysis & Direction
  ### 3.1 What works (> baseline)
    - Context readback (champion/DRP): +0.0118 vs baseline, confirmed effective
    - Token regularization (ORT): 0.5005, modest gain from token diversity
    - Token FFN refinement (CTF): 0.4995, token quality helps but doesn't break ceiling
    - Detail message type (D1): 0.5003, detail representation close to champion

  ### 3.2 What failed (< baseline or ineffective)
    - Learned weights (WCA 0.4890, gate series): learned weighting consistently underperforms
    - Feature-level modulation (FLM 0.4865): linear modulation insufficient
    - Inter-cluster attention (C2C 0.4865): cross-token interaction not beneficial
    - Routing (true_route 0.4468): routing actively harmful

  ### 3.3 What needs ablation
    - Readback expressiveness: all ceiling-hitting experiments use the same linear/additive readback
    - Point-conditionality: no experiment has tested whether readback should depend on point features
    - Nonlinear mapping: no experiment has tested whether the cluster_msg->feat mapping benefits from nonlinearity

  ### 3.4 Conclusion
    - All experiments hitting 0.5012 use `feat += gate * W(msg)` — a purely linear/additive readback
    - The bottleneck is likely in readback expressiveness, not token quality
    - Next: test two dimensions of readback expressiveness: conditionality (BIL) and nonlinearity (NLR)

## 8. Smell Check (Phase 1.6)

  ### M48-BIL:
  - Smell signals: None triggered
    - #1 (params<5K): 131K new params, PASS
    - #2 (single operator): Bilinear interaction (element-wise product of two projections), not a single LayerNorm/Linear/Scaling, PASS
    - #3 (numerical distribution change): New computation path, not just normalization/scaling, PASS
    - #4 (hyperparam sweep): No tunable hyperparameters, PASS
    - #5 (renaming to bypass): Genuinely different from gate/film/residual, PASS
    - #6 (find better numerical config): New computation graph structure, PASS
  - Causal mechanism: "Point features with different semantic profiles (foreground/background/boundary) should receive different cluster context updates. The bilinear interaction W_p(feat) * W_c(msg) makes the readback depend on the point's own state."
  - Verdict: PASS — new computation graph, clear causal hypothesis, no hyperparams to tune

  ### M49-NLR:
  - Smell signals: #2 borderline (could be seen as "added an MLP to X")
    - #1 (params<5K): 524K new params (256->1024->256), PASS
    - #2 (single operator): 2-layer MLP with 4x expansion is a substantial structural change, not a trivial single-layer addition. Compares to: CTF's per-token FFN (~262K params) which was accepted. NLR is a different mechanism (post-gather vs pre-gather FFN).
    - #3-#6: PASS for same reasons as BIL
  - Defense for #2: A 2-layer MLP with 4x hidden expansion (256->1024->256) is structurally equivalent to the FFN module used throughout this codebase (dec.py line 116: FFN class uses Linear->Act->Linear). The key difference is WHERE it's applied: on the readback message rather than in attention layers. This tests a genuine hypothesis about the need for nonlinearity in the readback path.
  - Causal mechanism: "If the cluster context->point feature mapping requires interaction between different dimensions of the cluster message, a linear projection cannot capture this. A 2-layer MLP with hidden expansion enables dimension mixing and nonlinear transformation."
  - Verdict: PASS — substantial parameter count, clear causal hypothesis, structurally equivalent to existing FFN patterns in the codebase
