## 1. Motivation（为什么设计这批实验）
  - 项目动机: cluster: 多尺度 cluster context 机制 — cluster bank 聚合点云特征→cluster_attn 把多尺度 context 回写更新 inst_feats→提升定位精度。目标 mIoU ≥ 0.51
  - 故事线当前状态: DRP 0.5012 证实 routing=死代码, context readback alone 驱动全部增益。三个有效机制 (context/ORT/detail) 全部止步 ~0.5005。FLM (multiplicative) running, C2C (intra-scale attn) waiting, SWI (sigmoid gate) waiting。所有实验聚焦 readback 机制 — 聚合步骤 (points→cluster tokens via mean-pool) 完全未探索
  - 触发原因: waiting=2 < 可用卡2+1=3, 队列深度不足。DRP 终态后队列从 3→2
  - 这批变体在故事线中的角色: 填补 "cluster token quality" 缺口 — 测试 per-token FFN refinement 是否提升 context 质量。与 FLM(注入范式)/C2C(token交互)/SWI(scale融合) 正交互补

## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline）
    - cluster context readback: champion/DRP 0.5012, γ=+0.0118 — 核心有效
    - ORT orthogonality: 0.5005, γ=+0.0111 — cluster 多样性重要
    - detail message_type: 0.5003, γ=+0.0109 — 等效机制
    - **DRP key finding**: 删除全部 routing 计算 → 0.5012 = champion. routing=死代码
  ### 3.2 哪些方向失败（< baseline 或持平）
    - CMX max-pool: 0.4910 — mean > max for aggregation
    - refine 系: CSR 0.4875, REF 0.4892 — refine 方向关闭
    - 机制组合: 全部 < 单机制 — 组合轴饱和
    - Q2P query-to-point: 0.4904 — 直接 query 注入无效
    - S2FM/S2FC 2-scale: 0.4933/0.4944 — 3-scale 必要
  ### 3.3 尚未消融的维度
    - **Cluster token quality (本次)**: token 形成后无 refinement, 直接用于 readback
    - Token interaction: C2C 队列中 (intra-scale self-attention)
    - Injection paradigm: FLM running (multiplicative)
    - Scale fusion: SWI waiting (sigmoid vs softmax)
    - **Aggregation method**: mean-pool only (max worse, dual untested separately)
  ### 3.4 结论
    - Ceiling 0.5012: 四个独立机制 (context/ORT/detail/DRP) 全部 ~0.5005, 暗示瓶颈在 token 质量或 decoder capacity
    - FLM/C2C/SWI 覆盖 readback 和 token interaction 维度
    - CTF 是唯一测试 "token 自身是否需要 refinement" 的实验
    - 基于 DRP 架构 (clean baseline, no routing dead code)
