## 3. Analysis & Direction (new this tick)
### 3.1 Existing evidence is exhausted
Eight query/region scoring variants and fifteen phrase-group variants were tested
on the same fixed forward. None ranks the query that covers the target above
roughly uniform: best median rank 12-14 (already the deployed head), all
region/phrase variants median rank 50-103 with margins ~1e-3.

### 3.2 The needed structure exists in the annotation
31/33 recoverable failures carry a content relation (29), another mentioned entity
(31) or an attribute contrast (21). Two failures have none.

### 3.3 Root cause: the referent supervision unit
`match_sampled_ins` marks as referent positives the single centroid-nearest query
plus every query whose seeded superpoint carries the GT instance id; mask agreement
is never required. `loss_indi` then trains the deployed head on that set.

So the head learns "my seed point lies inside the referred object" (a point-level
question) although deployment asks "which object hypothesis is the referred one"
(an object-level question). The head's input, the query embedding, contains no
signal about the extent of the object its mask proposes. Two same-name neighbours
at 2.03 m have near-identical local geometry, so the point-level question is not
learnable to object-level accuracy from the inputs the head receives.

### 3.4 Derived candidate mechanism (to be argued before admission)
**Object-Hypothesis Referent Supervision (OHRS).** Keep the architecture and the
query set unchanged; change what the referent decision is trained to be, so that
the deployed score is computed from the *object hypothesis a query induces* rather
than from the seed point alone.

Forward: for query i with predicted mask m_i, form the mask-supported evidence
e_i = f(m_i, inst_feats) using only operators already in the model's computation
graph (no new detection source, no GT instance access).
Loss: positives for the referent head are the queries whose *hypothesis agrees
with the referred instance*, with the current seed-based set retained only as a
bootstrap term for the first warm-up phase; the referent likelihood is then
supervised on the object-level question.

Cost: no new parameters are required by the supervision change itself; the pooled
evidence uses an existing operator, so the FLOPs delta must be measured against the
historical <=10.0G and the ~0.24G headroom.

Expected result if the causal story is right: the correct query stops being rank
12-14 and the 33 recoverable failures convert; overall mIoU moves toward .51.
Disconfirming result: the object-level positives change training but the deployed
rank of the correct query stays ~uniform, which would mean the query embedding
itself, not its supervision target, is the limiting factor.

## 7. Risk Assessment
The seed-based positives are not wrong by themselves: they bootstrap training when
masks are poor. Removing them too early can starve the head. A warm-up schedule is
therefore part of the mechanism, not a tuning knob, and it must be justified from
the training dynamics rather than chosen for convenience.

If positives are defined by mask agreement, the head can be trained on queries the
matcher would not select; the interaction with `loss_masks` and `loss_scores` must
be checked so the referent head is not simply learning to imitate the mask head.
That imitation failure mode is the main disconfirmation to test first.

## 8. Smell Check
No sweep, seed, optimizer, schedule, weight or threshold change is proposed here.
The change is to what the referent decision is trained to answer, which meets the
"new loss changes the optimisation landscape" criterion, and the causal claim is
stated so that it can be falsified by the rank measurement already in place.
