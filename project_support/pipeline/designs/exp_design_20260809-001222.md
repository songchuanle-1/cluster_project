## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline 0.4894）
    - 多尺度 context 回写: DRP 0.5012 (γ=+0.0118) — 核心机制
    - detail message: D1 0.5003 (γ=+0.0109) — 独立有效
    - HCG 正确交付: M65 0.5002 (γ=+0.0108) — 修复缺陷, 但不带来新上限
  ### 3.2 哪些方向失败（≤ champion 或已闭合）
    - 交付轴: HCG 0.5002 ≈ champion — 闭合 (修复短板不破顶)
    - detail×HCG: M66 0.4955 — 负交互 (正确对齐的 context 被残差化)
    - 迭代单轴: M69 0.4978 < champion — **疑似受限缺陷交付**
    - 融合权重/门控/聚合/顺序/orth: 全 ≤ champion (各轴闭合)
    - routing: 证伪 (-0.0544)
  ### 3.3 尚未消融 / 结构空白
    - **{迭代}×{交付 HCG}**: iter×HCG, reag×HCG — 本次填补 (唯一空格)
    - {迭代}×{message}: iter×detail (M75), reag×detail (M76) — 已在队列
    - {token质量}×{迭代}: CCP × 迭代 — CCP 结果未到, 组合时机未成熟
  ### 3.4 结论
    - M69-ITER 终态 0.4978 是本次设计的关键输入: 迭代 2 轮用的 `_cluster_to_points` 是
      Lite 缺陷版 (粗尺度 token 未真正交付到点)。因此迭代的"每轮多读一次 context"
      实际是"每轮多读一次准单尺度 context", 第二轮几乎没有新信息可吸收 → 0.4978 平台。
      HCG 单独 0.5002 证明正确交付有价值但单轮就饱和。两者从未正交: 迭代×HCG 让每轮
      都读到真多尺度 context, 第二轮 gather 在更丰富的输入上做精化 — 这是打破
      "0.50 平台" 的直接结构性假设。

    定位提升。M66 负交互是 detail 残差语义×正确对齐, 本设计是加性累积×正确对齐, 机制不同。
