## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline）
    - context 回写 (A1): 0.5012, γ=+0.0118 (核心, 已确认)
    - decoder-access qla (DCM): 0.5010, γ=+0.0116
    - 多层注入 legacy 2层 (MLay): 0.5010, γ=+0.0116
    - detail message (D1): 0.5003, γ=+0.0109
  ### 3.2 哪些方向失败（< baseline 或持平）
    - cluster token 结构变换: C2C=0.4865 (token 交互) / CSF=0.4958 (跨尺度融合) /
      FLM=0.4865 / pool 全灭 / TrueRoute=0.4468 (routing)
    - 通路组合: M125/M126/M134/M136/M138 — 全部不叠加 (0.495-0.499)
    - MFP/CSORT/CTF token-FFN / 池化类型: 全灭
  ### 3.3 哪些尚未消融
    - **cluster token 同尺度实例判别 (CLICA)**: M140 queued (本 tick 推送)
    - **cluster token 跨尺度实例一致 (CSIC)**: M141 queued
    - **双监督交互 (CLICA×CSIC)**: M142 queued
    - **cluster token 目标感知 (OBJG)**: M143 queued
    - **cluster token 语言语义对齐 (LQA)**: 未测 (本设计 M144)
    - {MLay 2层 legacy}×{DUAL}: M139 running (修正 M138 base 缺陷)
    - seed 矩阵: M120/M122 running+queued
  ### 3.4 结论
    - 平台瓶颈在 cluster token 信息量。CLICA (判别)、CSIC (一致)、OBJG (目标身份)
      三条 loss 路径已 queued, 但它们全部只用离散身份标签, 未把查询语言语义内容
      注入 token。LQA 是唯一语义维: 目标簇 token 与语言嵌入对齐 → 回写 context
      语义定向。与前三者信号源正交 → 独立赌注, 值得第四格。

## 7. Risk Assessment（风险评估）
  - 代码风险: 中低。纯 loss 级变更 + 复用 objg 的 token 暴露机制与目标 id 派生
    (已 py_compile), 不碰 cluster 注意力主干路径; 训练时开启, 推理不受影响。
    lang_emb 从 pred 的 proj_tokens 池化 (loss_sem_align 既有信号), 无新增前向。
    若 crash → 3 次自修复预算。
  - 资源风险: 低。新增参数 ~16.4K (仅对齐头), ~328 token 级 InfoNCE, 显存/FLOPs
    增量可忽略; 满足 ≤10G。
  - 数据风险: 无。复用 ScanRefer GT (sp_ref_masks + sp_ins_labels + object_idss
    均已在 loss forward) + 已有 proj_tokens/lang_masks。
  - 失败回退: 独立实验。若 LQA 不叠加 (≈0.501) → 与 M140/M141/M142/M143 交叉确认
    "loss 监督轴四维全部饱和", 平台需范式级新方向 (记为 question, 暂停自主
    设计, 等用户拍板新范式方向)。
