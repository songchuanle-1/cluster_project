### 3.3 Duplication

### 3.4 Conclusion
The multi-scale evidence-duplication hypothesis is answered affirmatively and
decisively. No scale, and not the whole message, changes the deployed referent
selection; the coarse scales are redundant mixtures and the gate already ignores
them. The cluster/scale/pooling/readback family is therefore closed as a route to
the target, on evidence rather than on preference.

The deployed bottleneck is one level up: 33 of 38 failures already contain a query
whose mask exceeds IoU 0.5 with the target (only 5 are mask-limited), and sampling
loses 0 of 117 covered targets. The answer exists; the wrong query is chosen.

### 3.5 Error type of the 33 wrong selections
Measured on the same report (selected mask versus the scene instance it overlaps
most, which is never a referred object):

| Quantity | Value |
|---|---|
| wrong selections whose selected mask reaches IoU > 0.5 with that other instance | 33/33 |
| median IoU with that other instance | 0.864 |
| selections segmenting that other instance perfectly (IoU >= 0.999) | 11/33 |
| selections with exactly zero overlap with the referred target | 28/33 |
| median referred-target size | 9 superpoints (scene median 40 instances) |

The model is not producing a blurry or split mask. It produces a clean, complete
segmentation of a different object, usually with no overlap at all with the target.
Combined with 3.1-3.3 this fixes the error type: referent identification, not mask
quality, not query coverage, not multi-scale aggregation. Targets are small and the
distractors are same-name neighbours (median 2.03 m).

### 3.6 Is the head merely mis-calibrated? (new this tick)
Same forward, comparing the deployed indis score with the query that actually has
the largest mask overlap with the target, over the 33 recoverable failures:

| Quantity | Value |
|---|---|
| selected indis above the correct query's indis | 33/33 |
| mean / median margin (correct minus selected) | -0.409 / -0.379 |
| cases that are near-ties (abs margin < 0.1) | 10/33 |
| median rank of the correct query in the indis ordering | 12th (max 97th) |
| mean indis of the selected vs the correct query | 0.873 vs 0.463 |
| selected mask already above IoU 0.5 with another instance | 27/33 (mean .740) |

The head is not marginally mis-ranked. It confidently prefers a different object
while the query that already solves the case sits around rank 12 with roughly half
the score. Re-weighting, re-scaling, re-ranking, contrasting or competing the
existing scores cannot recover evidence the head never receives; its only input is
the query embedding. A candidate mechanism must therefore *inject* identifying
evidence into the referent decision, and must be differentiable end to end.

### 3.7 Does any existing per-query signal separate the pair? (new this tick)
Same forward, restricted to the 33 recoverable failures, ranking the query that
actually covers the target against all 128 sampled queries:

| Signal | median rank of the correct query | mean rank | top-1 rate | selected value vs correct value |
|---|---|---|---|---|
| indis (deployed referent head) | 12 | 24.3 | 0% | .873 vs .463 |
| mask score head | 13 | 30.1 | 6.1% | .837 vs (margin .806) |
| sampling language-point correlation | 13 | 29.8 | 9.1% | .747 vs (margin .671) |

Supporting quantities: the correct query's mask covers the target almost perfectly
(best IoU mean .871 / median .933; mean target coverage .947), a median of 6 (mean
10.7) queries already exceed IoU 0.5 with the target, and the selected and correct
masks are usually disjoint (median overlap 0 points).

Three conclusions:
1. This is not one bad head. All three existing scalar scores place the objectively
   correct query around rank 13. The per-query scoring signal itself does not encode
   "this query covers the referred object".
2. The redundancy is extreme: the correct mask exists many times over (median 6
   usable queries), yet none of them wins. The failure is in *which* candidate is
   recognised as the referent, not in candidate generation.
3. Because the deployed score is an argmax, "selected outscores correct" is
   automatic and must never be cited as evidence. The non-trivial facts are the
   rank (§3.7), the magnitude of the gap (§3.6), and the near-absence of ties.

| 4 | scoring-unit change (score predicted regions, not queries) | absent | §3.7 shows the per-query scalar is the wrong unit | EFFICACY-LIKELY, NOVELTY-NEGATIVE so far | P0 | prior art |

Item 4 is the obvious repair suggested by §3.7 and it is deliberately NOT admitted
yet. Region-level language scoring is the dominant paradigm in 3D referring
segmentation (InstanceRefer / M3DRef / 3DVG-Transformer style heads score region
features against the language), so moving the referent decision from query space to
mask-region space may fix efficacy while adding no novelty. The goal's own novelty
constraint is explicit, so item 4 can only be admitted if the derivation adds a
mechanism that a generic region-language score does not already provide; otherwise
it is a known-good baseline, useful as a control, not as the contribution.

Requirements recorded for item 3 before any admission: structurally new forward or
loss (not a numeric change, not params<5K, not a single added operator); must change
what evidence the selection decision is computed from, not merely re-weight or
re-rank existing scores; must be compared against the whole computation in NS3D,
InstAlign, HCF-RES and JVGN; must exclude ranking, contrastive, IoU-competition,
reranking and assignment-successor designs; must report overall mIoU plus the
predefined 33 recoverable and 5 mask-limited strata with scene-level uncertainty.

## 7. Risk Assessment
Forward-only intervention at a trained checkpoint does not undo training effects;
the champion's gain over baseline must not be re-attributed to the forward path, nor
the branch declared useless. Mean selected IoU is a TRAIN quantity, not mIoU. 91 of
123 expressions repeat a scene geometry, so per-expression counts are not
independent samples; scene-level uncertainty is required for any later claim.
Dropping one scale inside a softmax gate does not renormalise the remaining
weights, so per-scale deltas are conservative lower bounds on necessity.
