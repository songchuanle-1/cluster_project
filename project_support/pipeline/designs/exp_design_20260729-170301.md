## 1. Motivation（为什么设计这批实验）
  - 项目动机: cluster: 多尺度 cluster context 机制 — cluster bank 聚合点云特征→cluster_attn 把多尺度 context 回写更新 inst_feats→提升定位精度。目标 mIoU ≥ 0.51
  - 故事线当前状态: DRP 0.5012 证实 routing=死代码, M34-Q2P 0.4904 证实 cluster tokens 是必要中间表示。四个机制 running/waiting (FLM/C2C/SWI/CTF) 全部操作在 token 形成之后。聚合步骤 (points→cluster tokens via mean-pool) 完全未消融。所有有效机制止步 ~0.5005 天花板 — bottleneck 怀疑在上游聚合。
  - 触发原因: waiting=2 < 可用卡2+1=3, 队列深度不足。M34-Q2P 终态后提供关键实验证据。
  - 这批变体在故事线中的角色: 填补 "cluster token 聚合质量 + 分布稳定性" 缺口。WCA 测试 better aggregation → better tokens 假设。CLN 测试 stable token distribution → better readback 假设。与 FLM/C2C/SWI/CTF 正交互补 (注入方式 / token 交互 / scale fusion / token refinement / 聚合方式 / 分布稳定 = 六个独立维度)。

## 3. Analysis & Direction（方向分析）
  ### 3.1 哪些方向有效（> baseline）
    - cluster context readback: champion/DRP 0.5012, γ=+0.0118 — 核心有效
    - ORT orthogonality: 0.5005, γ=+0.0111 — cluster 多样性重要
    - detail message_type: 0.5003, γ=+0.0109 — 等效机制
  ### 3.2 哪些方向失败（< baseline 或持平）
    - Q2P direct injection: 0.4904 ≈ baseline — cluster tokens 必要 (关键证据)
    - CMX max-pool: 0.4910 — mean > max for aggregation
    - DTW density-weight: 0.4968 — additive 注入天花板 (≤0.5005)
    - refine 系: CSR 0.4875, REF 0.4892 — refine 方向关闭
    - 机制组合: 全部 < 单机制 — 组合轴饱和
  ### 3.3 尚未消融的维度
    - **Cluster token 聚合质量 (本次)**: 仅 mean-pool 测试过, max 更差。Weighted aggregation (learnable per-point weights) 未测试
    - **Cluster token 分布稳定性 (本次)**: 无 normalization 消融
    - Injection paradigm: FLM running
    - Token interaction: C2C running
    - Scale fusion: SWI waiting
    - Token refinement: CTF waiting
  ### 3.4 结论
    - M34-Q2P 关键发现: 去掉 cluster tokens → 回 baseline。证明 cluster 机制必要, 但聚合方式可能粗糙
    - Ceiling 0.5012: 六个 running/waiting 实验测试五个维度 (injection/interaction/fusion/refinement/aggregation/normalization)
    - FLM 是突破 additive 天花板的最佳候选; WCA/CLN 是改进 token 形成质量的首次尝试
    - 基于 DRP 架构 (clean baseline, no routing dead code)

## 7. Risk Assessment（风险评估）
  - 代码风险: LOW — WCA 加 ~15行 (weighted branch in aggregate_cluster + SharedClusterBank weight_module), CLN 加 ~20行 (C2F_ClusterAttn_DRP_CLN class). 无结构性 API 变更, 无 CUDA 扩展, 无新依赖
  - 资源风险: LOW — WCA 多一次 Linear(d,1) per-point (token formation 时), CLN 多 3×LayerNorm (cluster tokens 上, M≤256 per scale). 开销远小于 backbone
  - 数据风险: NONE — 相同数据集, 零数据依赖变更
  - 失败回退: 
    - WCA ≤ 0.5012 → mean-pool 已最优, 关闭加权聚合方向
    - CLN ≤ 0.5012 → token 分布不是瓶颈, 关闭 normalization 方向
    - 如果都失败 → 所有 post-aggregation + in-aggregation 维度均已测试, 需重新审视假设 (decoder/backbone capacity)
    - crash 3 次 → 放弃, log question
