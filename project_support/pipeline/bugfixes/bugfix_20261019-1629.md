# Bugfix: 恢复观察守卫采用原生同口径序列化

- **时间**: 2026-10-19 16:09首次中止；16:15 CPU证明；16:29实际续训核实，上海时间。

- **错误日志摘要**:
  ```text
  unexpected key in source state_dict: text_encoder.embeddings.position_ids, text_encoder.embeddings.token_type_ids
  Loading optimizer from .../20261019_093003/last.pth
  Loading scheduler from .../20261019_093003/last.pth
  AssertionError: Model state restore mismatch
  ```
- **根因**: 原生gorilla.save_checkpoint使用自定义get_state_dict并保存两个非持久buffer；我新增的观察器却使用Module.state_dict（1163项），与原检查点1165项比较发生误判。两项是1x514的int64位置/类型索引，不是可学习参数，原生加载前的值就与保存值完全一致。
- **修复**:
  ```diff
  - model_state=kwargs['model'].state_dict()
  + from gorilla.solver.checkpoint import get_state_dict
  + model_state=get_state_dict(kwargs['model'])
  ```
- **证明**: 仅CPU构建原生模型、使用原生resume：1165个保存张量逐项精确相等，642项优化器state的所有张量无差异，scheduler全部保存字段相等，CUDA未初始化。没有删键、改模型、改配置或放宽数值标准。
