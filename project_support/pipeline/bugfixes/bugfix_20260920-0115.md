# Bugfix: Registry Runner Partial JSON Publication

- Time: 2026-09-20 01:15 Asia/Shanghai.
- Experiment: referent-causality-audit shared diagnostic; no training crash.
- Error type: partial persistence / incomplete capture evidence.
- Error evidence: direct json.dump to the final path can leave incomplete bytes
  when serialization or I/O fails. A partial capture marker is not completion.
- Root cause: previous dump_new opened the final artifact before serialization;
  no bundle-level completion/inventory/hash reader guarded downstream consumption.
- Fix: serialize first, write and fsync temporary bytes, publish with a
  no-overwrite hard link, always remove temporary file. Require exact complete
  bundle inventory and hashes, reject failure marker or leftover partial files.
- Retry: first local mocked CLI audit, fixed in synthetic/static tests.
- Executed coverage: exact binding load, capacity refusal, wrong loaded source,
  state-load failure, post-capture drift, missing/altered/duplicate/traversal
  artifacts, failed fsync and failed success-marker publication.
- Validation: 190 tests run, 188 passed, 2 skipped (Torch absent locally).
- Scope: original eleven-file runtime unchanged; separate runner only.
- No native run, training retry, model/config change, admission or deployment.
- Limits: native hard-link support unverified; no directory-fsync power-loss
  guarantee. Bundle hashes attest integrity, not native execution or science.
