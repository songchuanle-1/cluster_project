# Bugfix: corrupted research_work.json blocked every hourly tick for 5 hours

- **时间**: 2026-09-18 13:35 (+08:00)
- **影响**: 定时流水线（`Pipeline-cluster_project`），2026-09-18 09:07 至 13:07 的连续
  **5 个 tick 全部崩溃**，因此期间没有产生任何新实验设计或队列推送。
- **错误类型**: state-file corruption / invalid JSON
- **错误日志摘要** (`pipeline/headless/tick_20260918-130700.log`):
  ```
  Traceback (most recent call last):
    data = read(Path(project) / "pipeline/research_work.json", {"candidates": []})
  json.decoder.JSONDecodeError: Expecting value: line 573 column 1 (char 31756)
  ```
- **根因**: `research_work.json` 中出现 **7 处多余的独立逗号行**（第 573、972、1375、
  1739、2249、2809、3412 行）。每一处的形态完全相同：
  ```
        },     <- 原有证据项的结尾
  ,            <- 多余的分隔符
        {      <- 新插入的证据项
  ```
  即向 `evidence` 数组插入新条目时**手工做了字符串拼接**，重复了分隔逗号。插入的是同一
  组 `due_capture_readiness` 证据（每处均为 `..._20260917-2108.json` 之后追加
  `..._20260918-0808.json`），共 7 次，对应当时 7 个 blocked 候选，说明是**一次批量
  字符串编辑在 7 个位置各重复了一次分隔符**。`scripts/` 下没有任何脚本引用
  `due_capture_readiness`，也不是由某个 `.py` 写入的，所以这是**手工字符串编辑**而非
  程序化写入。
- **修复**: 删除 7 行多余的独立逗号行。
  ```
  removed stray comma lines: 7
  JSON VALID; candidates 25
  stages: {'rejected': 17, 'training': 1, 'blocked': 7}
  ```
  修复前先整文件备份到 `pipeline/research_work.json.corrupt_20260918`（保留原始损坏
  状态以备比对）。
- **完整性验证**:
  - `research_work.json`: 25 个候选、**869 条证据全部哈希校验通过，0 问题**，纯 ASCII。
  - 全量 JSON 校验：`queue.json`、`running.json`、`goal.json`、`closure_policy.json`、
    `admissions/*.json`、`experiments/*.json` 共 **185 个 JSON 文件，无效 0 个**（确认
    损坏只波及这一个文件）。
  - 工具链恢复：`build_tick_context.py` 正常完成（此前必崩），输出 mode=event、
    capacity 2、active 1、budget 1、research_work 候选 7（未终结的活动候选）。
- **预防**: 对 `research_work.json` 等状态文件的任何写入都必须走
  `json.load` / `json.dump`，禁止字符串拼接插入条目；批量改动后必须立即用
  `json.load` 回读校验。
- **训练影响**: **无**。M197-PIRS 全程未受影响（PID 1134192，当时 epoch 17/50，
  best 0.4803，`running`，`launch_verified=true`）。这次故障只影响流水线的设计与
  推送环节，不影响已启动的训练进程。
- **重试**: 第 1 次修复即通过；结果 **fixed**。
