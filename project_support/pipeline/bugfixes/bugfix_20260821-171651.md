# Bugfix: M117-BCF CUDA OOM — per-cluster padded attention → exact gather+projection

- **时间**: 2026-08-21 17:16:51
- **实验**: M117-CTF-HCG-BCF
- **错误类型**: CUDA out of memory (31.30/31.36 GiB on RTX 5090, first train step)
- **错误日志摘要**:
  ```
  torch.OutOfMemoryError: CUDA out of memory. Tried to allocate 20.00 MiB.
  GPU 0 has a total capacity of 31.36 GiB of which 10.69 MiB is free.
  ... this process has 31.30 GiB memory in use. Of the allocated memory 29.21 GiB is allocated by PyTorch
  File "...ctf_hcg_bcf/hier_postprocess.py", line 700, in forward
      attn_out, _ = self.bcf_attn[lvl](pts_padded.unsqueeze(0), cluster_kv, cluster_kv)
  ```
- **根因**: `BidirectionalContextFlow.forward` 对每个尺度每个簇把成员点 padding 到全量 N，
  并对每个簇单独跑 `nn.MultiheadAttention`（≈256 簇 × B × 3 尺度 ≈ 1500 次带 autograd
  图的注意力调用）。每次注意力中间张量 [1,N,C] 被保留用于反传，峰值堆积至 31.3 GiB。
  数学上每个点只 attend 到**单个 key**（自己的 cluster token），softmax over 1 个 key 恒为 1，
  Q 投影对输出无贡献且梯度为 0 → MHA 输出 ≡ `attn.out_proj(V_inproj(cluster_token))`。
- **修复**:
  ```diff
  - # 每个簇循环: padding 到 N + MHA 调用 (O(N²·K) 图保留)
  - for k in range(K):
  -     member_mask = (ids_b == k); member_pts = pf_b[member_mask]
  -     pts_padded = cat([member_pts, zeros(N - n_members, C)])
  -     attn_out, _ = self.bcf_attn[lvl](pts_padded, cluster_kv, cluster_kv)
  -     member_out = attn_out[0, :n_members]
  -     member_out = self.bcf_out_proj[lvl](member_out)
  -     level_bcf[b, member_indices] = member_out
  + # 每个点 gather 自己的 cluster token → V-inproj → attn.out_proj → bcf_out_proj
  + w_v = attn.in_proj_weight[2*C:]; b_v = attn.in_proj_bias[2*C:]
  + ct_pp = cf[b][ids_b]                          # [N_b, C]
  + v = F.linear(ct_pp, w_v, b_v)                 # V-inprojected cluster token
  + member_out = attn.out_proj(v)                 # MHA out_proj
  + member_out = self.bcf_out_proj[lvl](member_out)
  + level_bcf[b, :n_pts] = member_out
  ```
- **等价性验证**（server-4 remote, torch 2.8）: 单-key MHA 的 attention weights 全为 1，
  `out == out_proj(V_inproj(kv)).expand(N)` 精确匹配 (atol 1e-5)。Q 路径梯度恒为 0。
- **修复后内存**: 冒烟测试 B=2,N=256,K=[256,64,8] 峰值 0.02 GiB（修复前 OOM 31.3 GiB）。
- **重试**: 第 1 次，结果: fixed (已 commit aad0aee → sync server-4 + server-6)
