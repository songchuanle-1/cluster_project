# Bugfix: launch died with torch_shm_manager socket error (server-6 root filesystem full)

- **时间**: 2026-09-16 12:29 (+08:00)
- **实验**: M197-PIRS (attempt 1 of <=3)
- **错误类型**: runtime / environment (PyTorch DataLoader shared-memory manager)
- **错误日志摘要**:
  ```
  RuntimeError: torch_shm_manager at ".../torch/bin/torch_shm_manager":
  could not generate a random directory for manager socket
  ```
  8 occurrences in
  logs/train_model_base1_quard2_c2f_enc_lite_posA_l1_ctf_hcg_csort_pirs_20260916_122148.log
- **根因**: `/` (which hosts `/tmp`) was 100% full on server-6 (98G size, 94G used,
  **0 bytes available**). The launcher inherited the default `TMPDIR`, so
  `torch_shm_manager` could not create its random socket directory. `/dev/shm` had
  1007G free and `/data3` had 1.9T free, so the storage existed; only the default
  temp location was exhausted. The launch process itself stayed alive while its
  DataLoader workers kept failing, producing 0 validation steps.
- **修复** (pipeline launcher, not the candidate):
  ```diff
   env['LD_LIBRARY_PATH']=(env['CONDA_PREFIX']+'/lib:'+env['CONDA_PREFIX']+
       '/lib/python'+pyver+'/site-packages/torch/lib:'+env.get('LD_LIBRARY_PATH',''))
  +# torch_shm_manager needs a writable temp dir for DataLoader worker sockets. On
  +# server-6 the root filesystem (and therefore /tmp) reached 100% full, so every
  +# launch died with "could not generate a random directory for manager socket".
  +# Prefer a project-local temp dir on the data volume when one is writable, and
  +# keep the inherited TMPDIR otherwise.
  +_td=pathlib.Path(root).parent/'pipeline/tmp'
  +try:
  +    _td.mkdir(parents=True,exist_ok=True)
  +except OSError:
  +    _td=None
  +if _td is not None and os.access(str(_td),os.W_OK):
  +    env['TMPDIR']=str(_td)
   (root/'logs').mkdir(exist_ok=True)
  ```
  File: `C:/Users/chuanle song/.codex/skills/songcl_research_pipeline/closure.py`
  in `safe_launch`. The change is confined to the launch environment of the main
  launcher, falls back to the inherited `TMPDIR` when no project-local dir is
  writable, and does not touch the candidate code, the config, or the schedule.
- **外部任务**: a foreign job (`das_language/train.py`, PID 1141209) also runs on
  GPU7. `max_tasks_per_gpu` for GPU7 is 2, so co-residency is within the authorised
  configuration; the foreign job was not touched.
- **重试**: attempt 1 failed; after the fix, attempt 2 launched and was verified:
  `shm_errors=0`, native `Train[1/50]` steps increasing **382 -> 486** within the
  4686-iteration epoch, GPU7 at 34% / 13949 MiB. Result: **fixed**.
