# Bugfix: Exact Cause Partition Aggregate Key Mismatch

- **时间**: 2026-09-25 07:12:00 Asia/Shanghai
- **实验**: M95 exact native match-cause partition
- **错误类型**: RuntimeKeyError in aggregate summary
- **错误日志摘要**:
  ```
  File "m95_exact_match_cause_partition_20260925.py", line 359, in summarize
      query_counts[name] += row["target_positive_queries"][name]
  KeyError: 'target_positive'
  ```
- **根因**: Row-level cause counts used `all`, `nearest`, and `member`, while
  the summary loop addressed them with selector names.
- **修复**:
  ```diff
  - for name in query_counts:
  -     query_counts[name] += row["target_positive_queries"][name]
  + query_counts["target_positive"] += row["target_positive_queries"]["all"]
  + query_counts["target_nearest"] += row["target_positive_queries"]["nearest"]
  + query_counts["target_member"] += row["target_positive_queries"]["member"]
  + query_counts["other_gt_only"] += row["target_positive_queries"]["other_gt_only"]
  ```
  Added a summary regression test that exercises all four aggregate buckets.
- **重试**: 第 1 次，结果: fixed. Focused tests pass `9/9` locally and on
  server-6 CPU; the native analyzer completed and wrote no partial output
  before the failure.
