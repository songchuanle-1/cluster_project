# Bugfix: remote_train.sh / sync.sh PROJECT_DIR 在 Windows 下解析失败 → 队列推送静默失败

- **时间**: 2026-08-12 18:52:00
- **实验**: M84-DET-CTF-HCG（server-4 gpu0，曾连续推送失败 8 次）
- **错误类型**: 路径解析错误（非 crash，是脚本环境适配 bug）
- **错误日志摘要**:
  ```
  >>> 队列推送失败 [M84 CTF×HCG×detail ...] → server-4 gpu0 (第8次)
  （pipeline_monitor 的 verify_launched 未在远端检测到进程）
  ```
- **根因**: `scripts/remote_train.sh` 与 `scripts/sync.sh` 的 `PROJECT_DIR` 默认值写死为 Linux 路径
  `/home/songcl/3dres/project/cluster_project/Cluster`。Windows 本地运行时该路径不存在，
  `get_yaml_value()` 解析 `SERVERS.yaml` 失败（`HOST` 为空），`set -euo pipefail` 下静默退出
  （exit 1，无任何输出）。此外 remote_train.sh 此前用 `BASH_SOURCE` 派生出**相对** `./Cluster`，
  在 `cd ./Cluster` 之后再调用 sync.sh，导致 sync.sh 内相对 `./SERVERS.yaml` 解析到错误的 cwd。
- **修复**:
  1. `remote_train.sh` / `sync.sh` / `remote_resume.sh` 的 `PROJECT_DIR` 改为由脚本位置派生**绝对路径**：
     ```bash
     PROJECT_DIR="${PROJECT_DIR:-$(dirname "${SCRIPT_DIR}")/Cluster}"
     # SCRIPT_DIR=$(cd -- "$(dirname "${BASH_SOURCE[0]}")" &>/dev/null && pwd)  → 绝对路径
     ```
  2. 三个脚本的 `get_yaml_value()` 增加 `cygpath -m` 转换，把 Git Bash 的 `/d/...` 路径转成
     Windows Python 可读的 `D:/...`：
     ```bash
     file=$(cygpath -m "$file" 2>/dev/null || echo "$file")
     ```
  3. `remote_train.sh` 在调用 `sync.sh` 时显式透传 `PROJECT_DIR`：
     ```bash
     PROJECT_DIR="${PROJECT_DIR}" bash "${SCRIPT_DIR}/sync.sh" "${SERVER}"
     ```
- **重试**: 第 1 次（本 tick 诊断后修复），结果: **fixed** — M84 于 18:50:58 在 server-4 gpu0 成功启动（PID 140507）。
