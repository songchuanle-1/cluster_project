# 面向用户的研究简报

六段报告用于审计留档；会话简报用于回答“现在怎样、做成什么、接下来怎么办”。
只改展示，不改变准入、资源、调度、通知或项目写入权限。用户明确要求完整
报告、原始日志或状态 skill 的 0-4 母版时，遵循其要求。

## 默认写法

先写项目名和数据采集时间，统一使用上海时间；缓存同时注明原采集时间。
通常控制在约 25 行，不为压缩篇幅遗漏异常、运行实验或必要的用户决定。
使用以下四块，不再默认展开编号 0-5 的原始报告：

```text
<项目名>｜数据采集于 <上海时间>

结论：<目前有何进展或风险>。目标 <数值>，最佳 <数值>，还差 <数值>。

实验进展
| 实验（ID + 结构短名） | 当前情况 | 训练进度 | 最佳主指标 |
| ... | 确认训练中 / 进度待确认 / 已完成 / 等待资源 | ... | ... |
排队：<已核实的等待数量及关键依赖；未核实则写未知>。

本轮成果
- <实际做过的测试或改动> → <实测结果> → <这说明什么，仍不能说明什么>。

下一步
- <具体测试或动作，以及必须先满足的条件>。
- 需你确认：<仅在确有必要时出现，给出明确问题>。
```

该框是格式，不是预置事实；所有数值、动作和判断必须来自本次证据。
没有目标时写“未设置目标”；无法计算差距时写未知，不补造数值。
指标保持原记录单位和量级；“差 0.0080”不能随意写成“差 0.8%”。
详细报告已存在时可附一个文件链接，不贴完整路径或重述六段表格。

## 把状态说清楚

- 队列登记为 running 不等于已确认训练。进程未见或日志步数未增长时，
  写“登记为运行，训练进程/进度未确认”，并说明已观测到的异常。
- 已获准训练、已入队、已有进程、已确认训练步数增长，是不同状态。
  不能把“已获准”或“进程存在”写成“训练正常”。
- finish 校验通过只说明本轮检查和记录完成，不能写成“设计验证成功”。
  未执行、前置检查失败、本轮未完成、遗留占用待核对，应直接解释原因，
  不只输出 COMPLETED、postflight 或 LOCK_RECOVERY_REQUIRED 等机器状态。
- 实现问题、证据不足、核心假设被反证否定、等待外部资源要分开。
  没有新结果时写“本轮只完成状态检查，没有新的研究结论”，不制造成果。
- 本轮成果只使用本轮证据或收据中的变化量。累计筛选记录不是本轮实验数，
  历史 rejected 不是本轮训练失败数，修订不是新候选，也不据此算成功率。
- 未观测的数据写未知；引用缓存要给时间。连接失败不能写成“没有实验”；
  不能因为没有本轮统计就把本轮成果写成零。
- 无训练时直接说明属于“还没有可训练候选”“等待具体确认”“部署/资源故障”
  还是“项目主动暂停”；多种原因并存时分别列出。监控返回码为零不代表远端健康，
  优先解释紧凑视图中的 operational_issues；旧故障已解决时不继续当作当前阻塞。

## 只展示有用的信息

用“实验 ID + 一句话结构短名”代替长配置名；名称应来自实际实现，不编造含义。
默认保留当前进度、最佳主指标、关键阻塞，以及影响判断的服务器/GPU 信息。
其他指标、GPU 利用率明细、完整配置、进程号、哈希、租约和原始检查输出留在
详细记录中；若它们直接解释故障或用户明确询问，再有针对性地展开。
不把英文阶段标签、脚本返回码和令牌统计当作研究结论；保留这些底层记录，
不为美化报告改变状态、覆盖失败证据或在释放租约后补写项目报告。

下一步是计划，不得列入本轮已完成动作。需要新授权时说清需要什么授权；
已经有授权的常规工作不增加审批。准确执行时间只能来自实际保存的调度配置，
不能把“下一次检查”写成承诺何时修好或何时得到好结果。

## 授权交接与等待

- 需要人工动作时，不能只报“授权阻塞”。说明候选 ID、已验证的具体文件范围、
  要求的操作及其边界；本地提交、推送、准入与启动训练分开表达。
- 在所属会话一次性提出明确问题。用户在本会话的无歧义确认可按项目契约留档，
  不要求固定口令或用户手写 JSON；不得把模型生成的提醒当作用户授权。
- 尚未获得确认就如实等待；同一阻塞未变时不重复索要相同确认。真正的新证据、
  到期复查或授权到达才续做，已有授权的工作不重复审批。
- 先检查已有的项目级或候选级授权是否覆盖本次操作，明确缺少哪一项，不默认
  每个新候选都要逐步重新审批。通用“修复流水线”不等于提交候选或训练授权。
- 可推进储备、待人工、待资源分开统计；暂停候选不冒充可用储备。只要仍有准备
  预算，继续其他合法独立工作。总候选数到上限或已排队项占满准备目标时才等待，
  不为清空计数删除历史、不伪造新成果。复查不是进展，也不是自动授权。
- 准入凭据失效、依赖未完成、进程观测失败、认领待核验和启动失败分别报告；
  不统一写成缺任务或待授权。认领恢复须说清已核实的阶段，无法确定是否启动
  时保留现场，不把超时当成重启许可。源码不一致须核查实际文件，不能只看提交号。
